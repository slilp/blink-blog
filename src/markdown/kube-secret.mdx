Some configs are sensitive data for example: database passwords, tokens, ssh keys, etc. So to storing the sensitive information need to use specific mechanism.

Kubernetes provides a built-in mechanism called Secrets to handle such sensitive data securely.

## Kubernetes Secrets

Kubernetes supports several types of secrets. The most common is the `Opaque` type, which allows you to store any custom data you need.

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: my-secret-base64
  namespace: my-app
type: Opaque
data:
  # The value must be Base64 encoded values
  # username: admin (echo -n 'admin' | base64)
  username: YWRtaW4=
  # password: P@ssw0rd (echo -n 'P@ssw0rd' | base64)
  password: UEBzc3cwcmQ=
```

```bash
kubectl apply -f my-secret-base64.yaml
```

<MdxImage src="/blog/kube-secret_1.png" alt="secret_1" />

Although you need to encode the values in base64 format, when you use the secret in a pod, Kubernetes automatically decodes the values for you. You don't need to manually decode them in your application code.

```yaml
apiVersion: v1
kind: Pod
metadata:s
  name: test-secret-decode
  namespace: my-app
spec:
  containers:
    - name: busybox
      image: busybox:latest
      command: ["/bin/sh", "-c"]
      args:
        - |
          echo "=== Testing Automatic Base64 Decoding ==="
          echo ""
          echo "Username from env: $MY_USERNAME"
          echo "Password from env: $MY_PASSWORD"
          echo ""
      env:
        - name: MY_USERNAME
          valueFrom:
            secretKeyRef:
              name: my-secret-base64
              key: username
        - name: MY_PASSWORD
          valueFrom:
            secretKeyRef:
              name: my-secret-base64
              key: password
      volumeMounts:
        - name: secret-volume
          mountPath: /etc/secrets
          readOnly: true
  volumes:
    - name: secret-volume
      secret:
        secretName: my-secret-base64
  restartPolicy: Never
```

## Secrets from HashiCorp Vault

As you can see above, Kubernetes Secrets work well for basic use cases, but they have a security limitation: **anyone with access to the cluster can view and decode the secrets**. Since secrets are only base64-encoded (not encrypted), any user with kubectl access can easily extract them:

To enhance security and restrict access to only authorized users and applications, you can integrate Kubernetes with HashiCorp Vault. Vault provides:

**Real encryption** : not just encoding

**Access control** : specific users/apps can access specific secrets

**Audit logging** : track who accessed what and when

### Using Vault Agent Sidecar Injection

Vault Agent Sidecar Injection is a method where Vault automatically injects secrets directly into your pods without creating Kubernetes secrets. This is more secure because secrets never touch the Kubernetes API or etcd.

Install Vault Agent Injector:

```bash
helm repo add hashicorp https://helm.releases.hashicorp.com
helm repo update

helm install vault hashicorp/vault \
  --namespace vault \
  --create-namespace \
  -f values_setup.yaml
```

```yaml
# Development HashiCorp Vault Configuration WITHOUT TLS and WITHOUT Persistent Storage
# WARNING: This is ONLY for learning - data will be lost when pods restart
# Uses in-memory storage instead of Raft

global:
  enabled: true
  tlsDisable: true

injector:
  enabled: true # Enable Vault Agent Injector for sidecar injection

server:
  # Development mode - in-memory storage
  dev:
    enabled: true
    devRootToken: "root" # Root token for easy access (NEVER use in production)

  # HA disabled for dev mode
  ha:
    enabled: false

  # Standalone mode
  standalone:
    enabled: true

  # Resource limits
  resources:
    requests:
      memory: 256Mi
      cpu: 250m
    limits:
      memory: 512Mi
      cpu: 500m

  # Service configuration
  service:
    enabled: true
    type: ClusterIP
    port: 8200
    targetPort: 8200

  # Readiness probe
  readinessProbe:
    enabled: true
    path: "/v1/sys/health?standbyok=true&sealedcode=204&uninitcode=204"

  # Liveness probe
  livenessProbe:
    enabled: true
    path: "/v1/sys/health?standbyok=true"
    initialDelaySeconds: 60

# UI configuration
ui:
  enabled: true
  publishNotReadyAddresses: true
  activeVaultPodOnly: false
  serviceType: "ClusterIP"
  serviceNodePort: null
  externalPort: 8200
```

After install your token will be `root` (only for learning purpose).

You can expose to access Vault UI:

```bash
kubectl port-forward svc/vault 8200:8200 -n vault
```

Next step we need to create a service account with proper role binding to allow access to Vault

Step 1 : Enable Kubernetes Authentication Method

```yaml
kubectl exec -n vault vault-0 -- sh -c "
export VAULT_TOKEN=root
vault auth enable kubernetes || echo 'Kubernetes auth already enabled'
"
```

Step 2 : Tell Vault how to communicate with your Kubernetes cluster

```yaml
kubectl exec -n vault vault-0 -- sh -c "
export VAULT_TOKEN=root
vault write auth/kubernetes/config \
kubernetes_host=\"https://kubernetes.default.svc:443\" \
disable_iss_validation=true
"
```

Step 4 : Bind Kubernetes service accounts to Vault policies

Create service account in Kubernetes

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: my-app-sa
  namespace: my-app
```

```yaml
kubectl exec -n vault vault-0 -- sh -c "
export VAULT_TOKEN=root
vault write auth/kubernetes/role/my-app-role \
bound_service_account_names=my-app-sa \
bound_service_account_namespaces=my-app \
policies=my-app-policy \
ttl=24h \
audience=\"https://kubernetes.default.svc\"
```

Ready ! Now you can create your pod with Vault Agent Sidecar Injection to automatically inject secrets from Vault into your pod.

---

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: busybox-vault-test
  namespace: my-app
  annotations:
    # Enable Vault Agent Injector
    vault.hashicorp.com/agent-inject: "true"

    # Vault connection settings
    vault.hashicorp.com/role: "myapp-role"

    # Inject db_user secret
    vault.hashicorp.com/agent-inject-secret-db_user: "secret/data/database"
    vault.hashicorp.com/agent-inject-template-db_user: |
      {{- with secret "secret/data/database" -}}
      {{ .Data.data.db_user }}
      {{- end -}}

    # Inject db_password secret
    vault.hashicorp.com/agent-inject-secret-db_password: "secret/data/database"
    vault.hashicorp.com/agent-inject-template-db_password: |
      {{- with secret "secret/data/database" -}}
      {{ .Data.data.db_password }}
      {{- end -}}

    # Prevent Vault Agent from staying running after init
    vault.hashicorp.com/agent-pre-populate-only: "true"
spec:
  serviceAccountName: myapp-sa
  restartPolicy: Never
  containers:
    - name: busybox
      image: busybox:latest
      command: ["/bin/sh"]
      args:
        - "-c"
        - |
          echo "=== BusyBox Vault Test ==="
          echo ""

          # Wait for secrets
          echo "Waiting for secrets..."
          while [ ! -f /vault/secrets/db_user ]; do
            sleep 1
          done

          echo "✓ Secrets injected!"
          echo ""
          echo "========================================="
          echo "DATABASE CREDENTIALS FROM VAULT"
          echo "========================================="
          echo ""
          echo "Username: $(cat /vault/secrets/db_user)"
          echo "Password: $(cat /vault/secrets/db_password)"
          echo ""
          echo "========================================="
          echo ""
          echo "Secret files location:"
          ls -lh /vault/secrets/
          echo ""
          echo "Test completed successfully!"
```
