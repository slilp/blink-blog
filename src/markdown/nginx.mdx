Nginx is a powerful, high-performance web server that has become the backbone of modern web infrastructure.

In this article, I'll explore the key functionalities of Nginx and how to implement them.

## Installation

You can easily set up Nginx using Docker Compose for development and testing purposes:

```yaml
version: "3.8"

services:
  nginx-learning:
    image: nginx:alpine
    container_name: nginx-learning
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx-config/nginx/nginx.conf:/etc/nginx/nginx.conf
      - ./nginx-config/nginx/default.conf:/etc/nginx/conf.d/default.conf
      - ./nginx-content/nginx:/usr/share/nginx/html
      - ./nginx-logs/nginx:/var/log/nginx
    restart: unless-stopped
```

In this setup, you should focus in `nginx.conf` and `default.conf`.

`nginx.conf` is the master file that dictates how Nginx software runs overall, while `default.conf` handles the configuration for specific websites or servers and is loaded by the main configuration file.

`nginx.conf`

```nginx
events {
    worker_connections 1024;
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;
    error_log /var/log/nginx/error.log;

    sendfile on;
    keepalive_timeout 65;

    include /etc/nginx/conf.d/*.conf;
}
```

## 1. Web Server

Nginx act as a web server for serving modern applications, particularly Single Page Applications (SPAs) like React, Vue, or Angular apps.

Here's a basic deploy react app with nginx server:

```dockerfile
# Build stage
FROM node:18-alpine as build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Production stage
FROM nginx:alpine
COPY --from=build /app/build /usr/share/nginx/html

RUN echo 'server { \
    listen 80; \
    server_name localhost; \
    root /usr/share/nginx/html; \
    index index.html; \
    location / { \
        try_files $uri $uri/ /index.html; \
    } \
}' > /etc/nginx/conf.d/default.conf

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

```

## 2. Static File Hosting with Performance Optimization

Nginx is exceptional at serving static files with various performance optimizations and caching strategies.

`default.conf`

```nginx
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html index.htm;

    # Enable gzip compression
    gzip on;
    gzip_vary on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml text/javascript;

    # Cache static assets
    location ~* \.(jpg|jpeg|png|gif|ico|css|js)$ {
        expires 1y;                                    # File expires in 1 year
        add_header Cache-Control "public, immutable";  # Can be cached publicly, never changes
        add_header Vary Accept-Encoding;               # Different cache for compressed versions
    }

    # Cache HTML with shorter expiry
    location ~* \.(html|htm)$ {
        expires 1h;
        add_header Cache-Control "public";
    }

    # No cache for API endpoints
    location /api/ {
        expires -1;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        return 200 "API endpoint - Method: $request_method, URI: $request_uri\n";
        add_header Content-Type text/plain;
    }

    location / {
        try_files $uri $uri/ =404;
    }

    location /status {
        access_log off;
        return 200 "Nginx is running!\n";
        add_header Content-Type text/plain;
    }
}
```

> Nginx does not have any cache mechanism by itself. The `expires` and `Cache-Control` headers are for browsers and CDNs to cache the data.

## 3. Reverse Proxy

Nginx's reverse proxy functionality allows it to forward requests to other servers.

In this section,I have 2 servers deployed at app1 and app2.

```
  app1:
    image: nginx:alpine
    container_name: app1
    volumes:
      - ./nginx-content/app1:/usr/share/nginx/html

  app2:
    image: nginx:alpine
    container_name: app2
    volumes:
      - ./nginx-content/app2:/usr/share/nginx/html
```

`default.conf`

```nginx
server {
    listen 80;
    server_name localhost;

    location /app1/ {
        proxy_pass http://app1:80/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /app2/ {
        proxy_pass http://app2:80/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        return 200 "Reverse Proxy - Use /app1/ or /app2/\n";
        add_header Content-Type text/plain;
    }
}
```

This set up allows you to access the two applications via:

If user access to `http://localhost/app1/dashboard` it will be proxied to `http://app1:80/dashboard`.

> Alert! Don't forget the trailing slashes!

Without trailing slashes

If user access to `http://localhost/app1/dashboard` it will be proxied to `http://app1:80/app1/dashboard` so that wrong !.

## 4. Load Balancing

Nginx provides several load balancing methods to distribute traffic across multiple backend servers.

In this section,I have 3 backend servers deployed at backend1, backend2 and backend3.

```
  backend1:
    image: httpd:alpine
    container_name: backend1
    volumes:
      - ./nginx-content/backend1:/usr/local/apache2/htdocs

  backend2:
    image: httpd:alpine
    container_name: backend2
    volumes:
      - ./nginx-content/backend2:/usr/local/apache2/htdocs

  backend3:
    image: httpd:alpine
    container_name: backend3
    volumes:
      - ./nginx-content/backend3:/usr/local/apache2/htdocs
```

`nginx.conf`

```nginx
events {
    worker_connections 1024;
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;
    error_log /var/log/nginx/error.log;

    sendfile on;
    keepalive_timeout 65;

    include /etc/nginx/conf.d/*.conf;
}

```

`default.conf`

```
server {
    listen 80;
    server_name localhost;

    location / {
        proxy_pass http://backend_servers;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

When I curl to the same path multiple times, You can see the requests are distributed to different backend servers.

## 5. HTTPS Configuration

Nginx makes it easy to implement HTTPS with SSL/TLS certificates, including automatic HTTP to HTTPS redirection.

`nginx.conf`

```
events {
    worker_connections 1024;
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;
    error_log /var/log/nginx/error.log;

    sendfile on;
    keepalive_timeout 65;

    # SSL optimizations
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    include /etc/nginx/conf.d/*.conf;
}
```

`default.conf`

```
# HTTP server - redirect to HTTPS
server {
    listen 80;
    server_name localhost;
    return 301 https://$server_name$request_uri;
}

# HTTPS server
server {
    listen 443 ssl http2;
    server_name localhost;

    # SSL Configuration
    ssl_certificate /etc/nginx/ssl/nginx.crt;
    ssl_certificate_key /etc/nginx/ssl/nginx.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;

    # Security headers
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options DENY always;
    add_header X-Content-Type-Options nosniff always;
    add_header X-XSS-Protection "1; mode=block" always;

    # Enable gzip compression
    gzip on;
    gzip_vary on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml text/javascript;

    location / {
        try_files $uri $uri/ =404;
    }

    location /status {
        access_log off;
        return 200 "Nginx HTTPS is running!\n";
        add_header Content-Type text/plain;
    }

    location /ssl-info {
        return 200 "SSL Protocol: $ssl_protocol\nSSL Cipher: $ssl_cipher\n";
        add_header Content-Type text/plain;
    }
}
```

If you want to test HTTPS locally, you can generate a self-signed certificate using OpenSSL:

```bash
mkdir -p ssl-certs

openssl genrsa -out ssl-certs/nginx.key 2048

openssl req -new -key ssl-certs/nginx.key -out ssl-certs/nginx.csr -subj "/C=US/ST=CA/L=San Francisco/O=Learning/OU=Nginx/CN=localhost"

openssl x509 -req -days 365 -in ssl-certs/nginx.csr -signkey ssl-certs/nginx.key -out ssl-certs/nginx.crt

rm ssl-certs/nginx.csr

chmod 600 ssl-certs/nginx.key
chmod 644 ssl-certs/nginx.crt
```

## Bonus : DDOS Protection

Nginx can help mitigate DDoS attacks by limiting the rate of incoming requests.

`nginx.conf`

```
events {
    worker_connections 1024;
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    # Rate limiting zones
    limit_req_zone $binary_remote_addr zone=general:10m rate=1r/s;

    # Connection limiting
    limit_conn_zone $binary_remote_addr zone=perip:10m;
    limit_conn_zone $server_name zone=perserver:10m;

    # Logging
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;
    error_log /var/log/nginx/error.log;

    sendfile on;
    keepalive_timeout 65;

    # Security settings
    server_tokens off;
    client_max_body_size 10m;
    client_body_timeout 60s;
    client_header_timeout 60s;

    include /etc/nginx/conf.d/*.conf;
}
```

`default.conf`

```
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html index.htm;

    # Connection limits
    limit_conn perip 10;        # Max 10 connections per IP
    limit_conn perserver 100;   # Max 100 connections total

    # Block common attack patterns
    location ~* \.(php|asp|aspx|jsp)$ {
        return 444;  # Close connection without response
    }

    location / {
        limit_req zone=general burst=10 nodelay;
        limit_req_status 429;

        # Block suspicious requests
        if ($request_method !~ ^(GET|HEAD|POST)$) {
            return 444;
        }

        try_files $uri $uri/ =404;
    }

    location /status {
        access_log off;
        allow 127.0.0.1;
        deny all;
        return 200 "Nginx is running with DDoS protection!\n";
        add_header Content-Type text/plain;
    }

    error_page 429 /429.html;
    location = /429.html {
        root /usr/share/nginx/html;
        internal;
    }
}
```
